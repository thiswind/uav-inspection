# 部署拆分重构记录

## 目标与边界

把能启动的程序与可选的大型数据分开交付；不重写业务算法，不移动或删除原始资料。

## 已确认问题

- 原目录约 16 GB，视频、本机虚拟环境、前端依赖、训练结果与源码混放。
- 启动脚本依赖作者个人 Conda/Node 绝对路径；同一后端为 8002/8003 重复启动。
- 数据路径同时依赖工作目录、源码目录和项目根目录，无法可靠独立移动。
- 部分 AI 依赖在导入时加载；植被总览必读历史结果，空数据时失败。
- 病虫害遥测在错误处理之外访问未初始化的数据库，导致预期回退失效。

## 实施方案

1. 统一通过 `deployment_paths.py` 解析 `UAV_DATA_DIR`；不指定时兼容原目录。
2. `optional_inference.py` 延迟加载模型及第三方 AI 库；不自动下载缺失模型。
3. 空视频/测量列表返回可用空状态；需要模型的操作明确返回缺少依赖/数据提示。
4. `deploy.py` 在接收方重建独立基础环境并构建前端，同一个后端提供网站。
5. 按白名单导出 `01-app` 和 `02-data`，不把依赖、训练副本、备份权重混入邮件包。
6. 使用缺数据、缺推理依赖、没有 MongoDB 的测试，以及前端构建和浏览器检查验收。

## 保留与移除

保留业务模块、接口和模型格式、原始文件、原有示例能力。只从交付物排除可重新安装的本机依赖和非运行必需的训练历史；消除重复后端进程与个人启动路径。

## 后续约束

新增运行数据路径必须通过统一路径模块；新增模型应延迟加载。基础环境不应导入 Torch/Ultralytics；所有可选资源缺失都应有明确空状态或可操作错误。打包始终创建新目录，不覆盖旧交付，不修改原始数据。
